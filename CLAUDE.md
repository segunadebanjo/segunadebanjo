# Insurance Ad Manager — CLAUDE.md

Multi-platform insurance ad management & campaign automation for an insurance brokerage.
Create → compliance-check → publish (PAUSED) → measure → optimize ads for six insurance classes on
Facebook, Instagram, Google Ads (Search + Display) and LinkedIn.

> Standalone app: it is kept separate from the NAICOM statutory-returns ERP add-on and shares no code
> or database with it.

## Tech decisions

- **ORM**: Prisma 6 (`prisma-client-js`, `provider = "mysql"`). `mysql2` is used by
  `scripts/wait-for-db.ts` and `scripts/apply-schema-sql.ts` (raw DDL path without Prisma).
- **Money**: every monetary column is `DECIMAL(12,2)` (`@db.Decimal(12, 2)`). Prisma returns
  `Decimal`, serialised as a **string** in JSON; the client converts with `Number()` for display
  only. Server-side arithmetic uses `Prisma.Decimal` or integer kobo/cents, never float accumulation
  for persisted values.
- **Currency** defaults to `NGN`.
- **AI**: `@anthropic-ai/sdk`, model `claude-opus-5-5` (override `ANTHROPIC_MODEL`), structured
  output via `client.messages.parse` + `zodOutputFormat`. If no `ANTHROPIC_API_KEY` is set (or the
  call fails/refuses), a deterministic template generator produces creatives so the app stays usable.
- **Sandbox**: `SANDBOX_MODE=true` routes every platform call to `SandboxAdapter` (fake external IDs,
  synthetic daily metrics) and simulates CAPI dispatches. Live adapters are used only when
  `SANDBOX_MODE=false` **and** the platform's credentials are present; otherwise that platform falls
  back to sandbox and `/api/platforms/status` says so.
- **Safety default**: publishing always creates platform objects in `PAUSED` state. Spend only starts
  after an explicit `POST /api/campaigns/:id/activate`.

Extra columns/tables beyond the original brief (utm_campaign, variant_id, keywords,
targeting_suggestions, dispatch_results, optimization_*) exist to support attribution, the publisher
and the rules panel.

### Attribution model
- `utm_campaign` is generated on campaign creation as `ins-<campaignId>-<slug>` and appended to every
  ad's landing URL together with `utm_source=<platform>&utm_medium=paid`.
- Webhook → `resolveAttribution()` (pure, unit-tested):
  1. click-id type → platform family (`fbclid`→META, `gclid`→GOOGLE, `li_fat_id`→LINKEDIN);
     `utm_source` refines META into FACEBOOK/INSTAGRAM and GOOGLE into SEARCH/DISPLAY.
  2. campaign from `utm_campaign` (`ins-<id>-…` pattern, else exact match on stored utm_campaign).
  3. if no campaign yet, inherit from an earlier event with the same `click_id` (funnel stitching).
  4. deployment = the campaign's deployment on the resolved platform (or the only one in the family).
- `POLICY_PURCHASED` increments `policies_sold` + `revenue_generated`, `QUOTE_STARTED` increments
  `quotes_started` on today's `performance_metrics` row of the attributed deployment.
- Duplicate `eventId` → 200 with `duplicate: true`, nothing re-counted or re-dispatched.

## Compliance rules (`services/compliance`)

Deterministic engine (`validateVariant`, `validateTargeting`) → each finding has
`{ code, severity: BLOCK|WARN, field, message, autoFixable }`. Variant status = BLOCKED if any BLOCK,
else WARNING if any WARN, else PASSED.

| Code | Severity | Rule |
|---|---|---|
| `PERSONAL_ATTRIBUTE` | BLOCK | Copy asserts/implies knowledge of the viewer's health, medical condition, financial distress, debt, credit, pregnancy, disability, etc. ("your diabetes", "struggling with debt?", "are you sick"). Meta personal-attributes policy. |
| `GUARANTEED_RETURN` | BLOCK | Unsubstantiated guaranteed returns/profits, "risk-free", "double your money", "100% guaranteed", "no risk". |
| `UNSUBSTANTIATED_CLAIM` | WARN | Superlatives / absolute promises ("cheapest", "best in Nigeria", "#1", "claims always paid", "guaranteed approval", "instant approval"). |
| `LICENSE_DISCLOSURE_MISSING` | BLOCK (Meta/LinkedIn) / WARN (Google) | Product's `regulatory_license_number` must appear in the primary text. Google RSA limits can't fit it, so it must be on the landing page (warning). Auto-fix appends `Licensed by NAICOM. Reg. No: <no>.` |
| `GOOGLE_HEADLINE_LENGTH` | BLOCK | RSA headline > 30 chars. Auto-fix trims at a word boundary. |
| `GOOGLE_DESCRIPTION_LENGTH` | BLOCK | RSA description > 90 chars. Auto-fix trims at a word boundary. |
| `GOOGLE_ASSET_COUNT` | BLOCK | RSA needs 3–15 headlines and 2–4 descriptions. |
| `GOOGLE_EDITORIAL` | WARN | Exclamation mark in headline, repeated punctuation, ALL-CAPS words (>3 letters, excluding known acronyms like HMO, SME, NAICOM). |
| `META_TEXT_LENGTH` | WARN | Meta headline > 40 chars or primary text > 500 chars. |
| `FEAR_PRESSURE` | WARN | Fear/pressure tactics ("before it's too late", "you'll lose everything"). |
| `SAC_ZIP_TARGETING` | BLOCK | Meta Special Ad Category campaigns can't target postal/ZIP codes. |
| `SAC_RADIUS_TOO_SMALL` | BLOCK | Meta SAC location radius must be ≥ 15 miles (24 km). |
| `SAC_DEMOGRAPHIC_TARGETING` | BLOCK | Meta SAC campaigns can't restrict age/gender. |

**Special Ad Category**: any campaign with a FACEBOOK/INSTAGRAM deployment is tagged
`FINANCIAL_PRODUCTS_SERVICES`, or `HOUSING` when the product class is `PROPERTY`
(`resolveSpecialAdCategory`). The Meta adapter always sends `special_ad_categories` and strips
age/gender/zip targeting.

**AI pre-flight** (`aiValidator.ts`): when `ANTHROPIC_API_KEY` is set, Claude reviews each variant for
subtler issues (implied personal knowledge, misleading claims, regulator-sensitive language) and
returns findings which are merged as **WARN** only — the deterministic engine is the only source of
BLOCKs, so results stay reproducible.

**Publishing gate**: `POST /campaigns/:id/publish` refuses (409) if any selected variant is BLOCKED or
targeting fails SAC rules.

## Authentication & roles
- Email/password; scrypt hashes (`services/auth/password.ts`); HS256 JWT in httpOnly SameSite=Lax cookie
  `iam_session` (`services/auth/session.ts`), signed with `AUTH_SECRET` (required in production).
- `middleware/auth.ts`: `requireAuth` reloads the user every request (inactive or tokenVersion mismatch → 401);
  `blockUntilPasswordChanged` (403 `PASSWORD_CHANGE_REQUIRED`); `writeRequiresMarketer` (non-GET needs
  ADMIN/MARKETER); `requireRole(...)`.
- Public: `/api/health`, `/api/auth/*`, `/api/webhooks/*` (API key). `/api/users` is ADMIN only; product DELETE is ADMIN only.
- Client: `src/auth.tsx` (`AuthProvider`, `useAuth().canWrite/isAdmin`, `RequireAuth roles=[…]`); any 401 signs the UI out.
- Forgot password (`services/auth/passwordReset.ts`): `/auth/forgot-password` always answers the same, at once (lookup + email
  run in the background); one-time sha256-hashed tokens, `PASSWORD_RESET_TTL_MINUTES`; reset bumps tokenVersion.
  Mail via `services/mail/mailer.ts`: `MAIL_TRANSPORT` smtp | log (dev console) | memory (tests, `outbox`). Links use `APP_URL`.
  morgan redacts `token=` from logged URLs.
- 2FA (`services/auth/totp.ts`, `twoFactor.ts`, `secretBox.ts`): login with 2FA on returns `{twoFactorRequired}` + 5-min
  `iam_mfa` cookie (aud `mfa`, path /api/auth); `POST /auth/login/2fa {code|recoveryCode}` issues the session (aud `session`).
  `REQUIRE_2FA_ROLES` → `mustSetUpTwoFactor` → `blockUntilAccountReady` 403 `TWO_FACTOR_SETUP_REQUIRED`. Replay guard via
  `totp_last_step` (conditional update). Admin `POST /users/:id/reset-2fa`. Tests: `freshCode()` clears last step.
- Always keep at least one active ADMIN (enforced on role change, deactivate, delete).

## Platform adapter contract (`services/platforms/types.ts`)

```ts
interface AdPlatformAdapter {
  readonly platform: Platform; readonly mode: 'live' | 'sandbox';
  publish(input: PublishInput): Promise<PublishResult>;          // always PAUSED
  setStatus(ref: ExternalRefs, status: 'ACTIVE' | 'PAUSED'): Promise<void>;
  updateBudget(ref: ExternalRefs, dailyBudget: number, currency: string): Promise<void>;
  fetchDailyMetrics(ref: ExternalRefs, since: Date, until: Date): Promise<DailyMetric[]>;
}
```
- `meta.ts` — Graph API v21.0: campaign (objective OUTCOME_TRAFFIC/OUTCOME_LEADS/OUTCOME_SALES,
  `special_ad_categories`, status PAUSED) → ad set (publisher_platforms facebook|instagram, geo only)
  → ad creative (link_data) → ad.
- `google.ts` — Google Ads REST v18: campaignBudget → campaign (SEARCH/DISPLAY, PAUSED) → adGroup →
  RSA adGroupAd + keyword criteria. OAuth refresh-token flow.
- `linkedin.ts` — Marketing API (`LinkedIn-Version: 202410`): campaign group → campaign (PAUSED,
  SPONSORED_UPDATES) → inline-content creative.
- `sandbox.ts` — deterministic fake IDs + seeded synthetic metrics per platform profile.

## Conversion dispatch (`services/conversions`)
- Meta CAPI: `POST graph.facebook.com/v21.0/{META_PIXEL_ID}/events` with `fbc` built from fbclid,
  sha256 email/phone, `event_id` for dedup, `custom_data.value/currency`.
- Google: `customers/{id}:uploadClickConversions` with gclid (+ hashed email user identifier for
  enhanced conversions), conversion action from `GOOGLE_ADS_CONVERSION_ACTION_ID`.
- LinkedIn: `POST api.linkedin.com/rest/conversionEvents` with `li_fat_id` (+ hashed email).
- Each platform is only sent events it can match (its own click id, or hashed email for Meta/Google/
  LinkedIn). Results stored in `dispatch_results`; `dispatched_to_platforms = any success`.

## Scheduled jobs (`jobs/scheduler.ts`, node-cron)
- `METRICS_SYNC_CRON` (default `0 * * * *`): sync yesterday + today metrics for published deployments.
- `OPTIMIZATION_CRON` (default `15 * * * *`): evaluate enabled rules; AUTO_APPLY rules act
  immediately (pause / raise budget via adapter), RECOMMEND rules create OPEN recommendations
  (de-duplicated per rule+deployment while OPEN).
- Disabled when `DISABLE_CRON=true` (tests).

## Conventions
- TypeScript strict on both sides; no `any` in exported signatures.
- Validate every request body with zod in the route; throw `HttpError(status, msg)`.
- Keep platform specifics inside adapters; routes talk only to services.
- Tests: `cd server && npm test` (vitest; pure functions, no DB needed — attribution uses an
  in-memory lookup implementation).
- Never commit real tokens; `.env` is git-ignored.

## Gotchas
- Zod 4: use `z.partialRecord(enum, …)` for optional-key maps (`z.record(enum, …)` is exhaustive).
- Prisma Decimals serialise to strings in JSON; the client must `Number()` them.
- LinkedIn ad accounts can't bill in NGN: budgets/spend are converted with `FX_NGN_PER_USD`
  (`LINKEDIN_ACCOUNT_CURRENCY`, default USD).
- Sandbox metric sync only accrues spend for ACTIVE deployments; the seeder uses the same
  deterministic `simulateDay()` so re-syncing doesn't jump.
